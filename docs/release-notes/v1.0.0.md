# Reflow Launcher 1.0 release notes

> **Draft.** These notes are a draft for the 1.0 GitHub Release, not a release announcement.
> The signing-certificate fingerprint below is final. Fill in "Verified on" before the first release candidate is tagged.

Reflow Launcher 1.0 is an Android home screen whose whole layout lives in one file,
`launcher.json`, in a folder you choose. Rearrange apps on your phone and the file updates.
Edit the file on your computer (or let an agent edit it) and the phone updates.

Available from [GitHub Releases](https://github.com/Nasawa/reflow-launcher/releases). F-Droid is planned next; Google Play later.
It runs on Android 10 or later. It doesn't ask for storage, accessibility, or "see all apps" permissions, and it never
connects to the internet. You give it one folder through Android's folder picker, and you can take that back at any time.

## What's in 1.0

- Home pages, a dock, folders, an app drawer (swipe up from the bottom, or the Apps button),
  and a title bar.
- A folder you and your AI agents can share: `launcher.json` (the layout), `status.json` (what the phone loaded and
  any problems), `apps.json` (your installed apps) and `AGENTS.md` (instructions for agents). Agents can tell the
  phone to reload with one command.
- The ⋮ menu shows the app's version, for example **Version 1.0.0**.

### Fixed since the test builds

- Swiping up right after the phone starts opens the app drawer.
- The phone and `validate.py` now accept the same numbers, and the phone keeps your numbers exactly as written when it saves.
- No more extra `.configlauncher (2)` folders. If the app is stopped mid-save, it restores your layout from its backup on the next launch.

## Known gaps

- **Cards aren't live yet.** Cards in `launcher.json` stay in the file and keep their place. On the phone they show a
  plain tile that says "Cards arrive in a later version.", and the Warnings list names each one. Live cards are
  planned for 1.1.
- **Foldables:** dragging icons on an open foldable has only been tested on an emulator so far, and menus can overlap
  the hinge on a half-open fold.
- **Not in 1.0:** a separate layout for a half-open fold, polish for very narrow split-screen and landscape windows,
  more title-bar options, and keeping edit mode, the drawer, folders and menus open when you rotate or fold (the
  current page is already kept).
- On a narrow screen, a long title-bar date can shrink to "O…".
- On very small phones (320 dp wide), a notice at the top can cut app labels partway through.

## Install and upgrade

**Reflow Launcher is a new app, not an update of Config Launcher.** After installing, set it as your Home app again
(it's listed as **Reflow**), pick the same folder and choose **Use the folder's layout**, and turn phone-only settings
such as **Label backdrop** back on. Uninstall Config Launcher once you're set up. The [rename notes](release-notes-reflow-rename.md)
have the details.

If you have been using the app without a folder (app-only mode), pick a folder *before* you
uninstall and let the app write your layout there. An app-only layout lives only in the app's
private storage and does not survive uninstall, and there is no in-app export. After you
install the release APK, set the app as your Home app, pick that same folder, and choose
**Use the folder's layout**.

If you already use a folder with a test build of the app, keep using that folder after the
reinstall and choose **Use the folder's layout** (not **Replace it with mine**, which would
overwrite your file).

Updates from 1.0 onward install in place and keep your folder and settings.

### For testers

- **The first install of a release build over any earlier dev or debug build needs one uninstall.** Debug and release
  builds are signed with different keys, so Android won't install one over the other. Builds from before the rename
  have a different package ID (see the [rename notes](release-notes-reflow-rename.md)), so they sit beside the new app
  until you uninstall them.
- Release-to-release updates (for example 1.0.0-rc1 to 1.0.0) are signed with the same release key, and each tag has a
  higher `versionCode` (`1.0.0-rc1` is 1000051; `1.0.0` is 1000099), so they install in place.
- Untagged or dev builds won't install over rc1 or 1.0 (`INSTALL_FAILED_VERSION_DOWNGRADE`): they use a lower
  `versionCode` (untagged builds are 1). Uninstall first, or, for an older build signed with the *same* key, use
  `adb install -r -d`. A debug APK still can't replace a release APK without an uninstall, because the keys differ.

## Check a download

The GitHub Release attaches `reflow-launcher-1.0.0.apk` and
`reflow-launcher-1.0.0.apk.sha256`. Check both of the following before you install.

1. The APK's SHA-256 must match the attached `.sha256` file. Keep the APK and the `.sha256` file in the same directory, then run:

   ```sh
   sha256sum -c reflow-launcher-1.0.0.apk.sha256
   ```

   That should print `reflow-launcher-1.0.0.apk: OK`.

2. The signing certificate must match the fingerprint below, and the copy in [`release-cert.sha256`](../../release-cert.sha256) in the repo. Compare the **certificate** digest (64 hex digits; ignore colons and case), not a public-key digest.

   Release certificate SHA-256: `7F:EF:63:96:CE:83:42:A5:EB:8C:BF:41:B1:EA:47:44:0F:BB:D5:9A:3D:EC:45:17:07:EC:74:04:D1:D1:4B:B4`

   ```sh
   apksigner verify --print-certs reflow-launcher-1.0.0.apk | grep "certificate SHA-256 digest"
   ```

   You should see one line such as `Signer #1 certificate SHA-256 digest: <fingerprint>` (some `apksigner` versions say `V3.0 Signer:` instead of `Signer #1`). The hex must match the fingerprint above and the non-comment line in `release-cert.sha256`.

`apksigner` is part of the Android SDK build-tools.
