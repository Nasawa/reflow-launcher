Reflow Launcher 1.0 is an Android home screen whose whole layout lives in one file,
`launcher.json`, in a folder you choose. Rearrange apps on your phone and the file updates.
Edit the file on your computer (or let an agent edit it) and the phone updates.

1.0 is published on [GitHub Releases](https://github.com/Nasawa/reflow-launcher/releases).
F-Droid and Google Play are planned later, using the same signing key so you can move between
those channels without reinstalling. It runs on Android 10 or later. The app does not use
storage, `QUERY_ALL_PACKAGES`, or Accessibility permissions, and it does not fetch from the
internet. You grant access to one folder through Android's system folder picker, and you can
revoke it.

## What's in 1.0

- Home pages, a dock, folders, an app drawer (swipe up from the bottom, or the Apps button),
  and a title bar.
- A config folder agents and humans can share: `launcher.json`, `status.json`, `apps.json`,
  `AGENTS.md`, and a `RELOAD` broadcast so the phone picks up edits.
- The first swipe up after a cold start opens the drawer ([#191](https://github.com/Nasawa/reflow-launcher/issues/191),
  [#259](https://github.com/Nasawa/reflow-launcher/pull/259)).
- The phone and `validate.py` agree on which JSON numbers are valid. Unedited numbers keep the
  exact text you wrote when the phone rewrites the file ([#120](https://github.com/Nasawa/reflow-launcher/issues/120),
  [#260](https://github.com/Nasawa/reflow-launcher/pull/260),
  [#261](https://github.com/Nasawa/reflow-launcher/pull/261)).
- The app no longer creates duplicate `.configlauncher (N)` folders. If it is stopped in the
  middle of a save, the next launch restores your layout from the backup copy
  ([#244](https://github.com/Nasawa/reflow-launcher/issues/244),
  [#251](https://github.com/Nasawa/reflow-launcher/pull/251),
  [#263](https://github.com/Nasawa/reflow-launcher/pull/263)).
- The ⋮ menu shows the version from the release tag, for example **Version 1.0.0**
  ([#255](https://github.com/Nasawa/reflow-launcher/issues/255),
  [#264](https://github.com/Nasawa/reflow-launcher/pull/264)).

## Known gaps

- **Cards are not live in 1.0.** Card entries stay in `launcher.json` and keep their cells, but
  they are not drawn. In a release build they show a plain tile that reads “Cards arrive in a
  later version.” Live dashboard cards are planned for 1.1
  ([#257](https://github.com/Nasawa/reflow-launcher/issues/257),
  [#265](https://github.com/Nasawa/reflow-launcher/pull/265)).
- **Real-hinge drag check.** The hands-on drag check on a real folding hinge was waived for 1.0
  (Christopher, 2026-11-10). Fold-open drag is emulator-tested only, best effort. It will
  be re-checked on a real foldable when one is available
  ([#253](https://github.com/Nasawa/reflow-launcher/issues/253)). Keeping overlays off a
  separating hinge is also later ([#226](https://github.com/Nasawa/reflow-launcher/issues/226)).
- Other work deferred past 1.0 includes the half-open fold layout override
  ([#224](https://github.com/Nasawa/reflow-launcher/issues/224)), some tight split-screen and
  landscape-banner polish ([#208](https://github.com/Nasawa/reflow-launcher/issues/208),
  [#204](https://github.com/Nasawa/reflow-launcher/issues/204)), further title-bar options
  ([#79](https://github.com/Nasawa/reflow-launcher/issues/79)), and keeping edit mode, the
  drawer, an open folder, and sheets when you rotate or fold
  ([#258](https://github.com/Nasawa/reflow-launcher/issues/258); the current page itself is
  already kept).

## Install and upgrade

**The first install of a release build over any earlier dev or debug build needs one
uninstall.** Debug builds and release builds are signed with different keys, so Android will
not install one over the other.

If you have been using the app without a folder (app-only mode), pick a folder *before* you
uninstall and let the app write your layout there. An app-only layout lives only in the app's
private storage and does not survive uninstall, and there is no in-app export. After you
install the release APK, set Reflow as your Home app, pick that same folder, and choose
**Use the folder's layout**.

If you already use a folder with a current Reflow build, keep using that folder after the
reinstall and choose **Use the folder's layout** (not **Replace it with mine**, which would
overwrite your file). If you are still on the old Config Launcher app, follow the
[rename notes](../release-notes-reflow-rename.md) first.

**Later updates from one release to the next** (for example 1.0.0-rc1 to 1.0.0, or 1.0.0 to a
later 1.x) install in place. They are signed with the same release key, and each tag has a
higher `versionCode` (`1.0.0-rc1` is 1000051; `1.0.0` is 1000099). Your folder grant, settings,
and Home-app role stay put.

**Untagged or dev builds will not install over rc1 or 1.0**
(`INSTALL_FAILED_VERSION_DOWNGRADE`). Those builds use a lower `versionCode` (untagged builds
are 1). Testers should uninstall first. If you are installing an older build signed with the
*same* key, you can instead use `adb install -r -d`. A debug APK still cannot replace a
release APK without an uninstall, because the keys differ.

## Check a download

The GitHub Release attaches `reflow-launcher-1.0.0.apk` and
`reflow-launcher-1.0.0.apk.sha256`. Check both of the following before you install.

1. The APK's SHA-256 must match the attached `.sha256` file:

   ```sh
   sha256sum -c reflow-launcher-1.0.0.apk.sha256
   ```

2. The signing certificate must match the fingerprint below, and the copy in
   [`release-cert.sha256`](../../release-cert.sha256) in the repo:

   ```sh
   apksigner verify --print-certs reflow-launcher-1.0.0.apk | grep "SHA-256"
   ```

   Release certificate SHA-256:

   `<RELEASE CERT SHA-256: to be filled in when the key is generated>`

`apksigner` is part of the Android SDK build-tools.
